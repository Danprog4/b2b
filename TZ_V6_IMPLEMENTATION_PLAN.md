# Сити Маркет — План имплементации (по ТЗ v0.6)

## 0. Как пользоваться этим файлом

### Цепочка документов
1. **`Техническое задание v6.txt`** (в `~/Downloads`) — первоисточник требований заказчика.
2. **`TZ_V6_COMPLIANCE.md`** — построчная code-verified сверка ТЗ с текущим кодом: что готово (✅), частично (🟡), не сделано (❌), баги (🐛), ждёт заказчика (⛔). Из неё выведены все задачи ниже.
3. **`TZ_V6_IMPLEMENTATION_PLAN.md`** (этот файл) — рабочий план: что делать, в каком порядке, как проверять, статус каждой задачи.

> Каждая задача ссылается на пункт ТЗ (`§…`) и на раздел `TZ_V6_COMPLIANCE.md`. Если по ходу всплывает расхождение — сначала правим/уточняем `TZ_V6_COMPLIANCE.md`, потом задачу здесь.

### Рабочий порядок
Идём строго сверху вниз: **Этап P0 → P1 → P2**. Внутри этапа — по порядку номеров (зависимости учтены). Клиентские блокеры (раздел C) и backlog (раздел B) — в самом конце; их берём по мере поступления данных.

### Статусы задач
- `⬜ TODO` — не начата.
- `🟦 IN PROGRESS` — в работе.
- `✅ DONE (code)` — реализована и самопроверена разработчиком (lint/build/логика), но человеком ещё не подтверждена.
- `🟢 VERIFIED` — проверена человеком вручную (финальная приёмка).
- `⛔ BLOCKED` — ждёт данных/ответа заказчика (см. раздел C).
- `🔁 RECHECK` — задача из backlog: пересверить после данных клиента.

### Правила обновления (ВАЖНО)
1. Беря задачу — ставь `🟦 IN PROGRESS`.
2. Закончив — меняй статус на `✅ DONE (code)` и **в поле «Изменения» коротко пиши, что и где сделал** (файлы, суть). Поле «Проверено человеком» оставляй `нет`.
3. Если задача упёрлась в данные клиента — `⛔ BLOCKED`, в поле «Изменения → блокер» укажи код клиентского пункта (C-XX).
4. **Человек (заказчик/тимлид) в конце проверяет вручную** каждую `✅ DONE (code)` задачу — включая адаптив (§25) и состояния экранов (§26), — и переводит в `🟢 VERIFIED`, проставляя «Проверено человеком: да».
5. Не удаляем выполненные задачи — оставляем историю со статусом.

### P1-02. Telegram-интеграция оператора

> **Принятое решение по архитектуре (зафиксировано):**
> - **Маршрутизация = Forum topics.** Группа операторов — супергруппа с темами. Каждый чат покупателя = отдельная тема; её `message_thread_id` храним в `chats.telegramThreadKey`. Ответ оператора в теме → находим чат по `telegramThreadKey`.
> - **Приём ответов = webhook.** Эндпоинт `POST /api/telegram/webhook` (с проверкой secret-token в заголовке `X-Telegram-Bot-Api-Secret-Token`). Для локальной разработки — туннель (ngrok/cloudflared) или временно polling `getUpdates`.
> - **Исходящие** (уведомление оператору, создание темы, вложения) — прямые вызовы Bot API, без webhook.
> - **Резервный ответ из админки** (`/admin/chats`) webhook не использует — пишет в БД напрямую, работает даже при недоступном Telegram.
> - Конфиг: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OPERATORS_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET`.
