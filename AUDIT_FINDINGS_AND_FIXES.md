## Что проверено и сделано надёжно (не трогать)

- **Статусы заказа** (`src/lib/orders/status.ts`): переходы строго ограничены
  `accepted→paid/cancelled`, `paid→issued/cancelled`, `issued/cancelled`→ничего (ТЗ 12.6).
- **Редактирование заказа админом** (`src/lib/admin/order-actions.ts`): только в `accepted`,
  защита от опустошения, смена предложения в рамках того же товара, пересчёт сумм/НДС/комиссии,
  пересоздание счёта, audit.
- **Отмена покупателем** (`src/lib/orders/actions.ts` `cancelAcceptedOrderAction`): только из
  `accepted`, уведомления покупателю/админу/продавцам.
- **Счёт** (`src/lib/invoices/generation.ts`): `isCurrent`/`replacedById`, старый скрыт,
  ошибка → `system_events` + повторная генерация; номер счёта в checkout переиспользуется.
- **Договор** (`src/lib/contracts/*`): нумерация `ДГ-`, генерация PDF, авто-формирование при
  регистрации и обновлении реквизитов, статус `requires_update`, перегенерация админом,
  раздел в ЛК.
- **Документы** (`src/lib/documents/actions.ts`): whitelist форматов + MIME + лимит 50 МБ,
  exe/bat/js заблокированы; приватная выдача с проверкой роли/компании/продавца.
- **Excel-импорт** (`src/lib/admin/product-import-actions.ts`): двухфазный, детект дублей
  `sku+продавец`, `pg_advisory_xact_lock`, дефолт НДС 22 %, автогенерация артикула.
- **Модерация** (`src/lib/admin/product-moderation-actions.ts`, `src/lib/seller/product-actions.ts`):
  правка продавца не трогает живой товар до одобрения (ТЗ 18.8), пересчёт приоритета,
  идемпотентность, уведомления о «перебитой цене».
- **Восстановление пароля** (`src/lib/auth/password-reset-actions.ts`): хэш токена, TTL 1 ч,
  одноразовый, не раскрывает существование email.
- **Чат/Telegram**: сообщение пишется в БД до отправки → при сбое не теряется, статус `failed`
  + system event.
- **UI пустые состояния**: заказы, документы, уведомления, товары продавца, каталог, карточка
  товара (`notFound()` + «Товар недоступен») — присутствуют. Submit-кнопки защищены от
  двойной отправки (`useFormStatus`).

## Доработки (по приоритету)

### P1 — функциональные, желательно закрыть

**1. Дробное vs целое количество — расхождение покупатель↔админ**
- Корзина допускает дробь: `sanitizeQuantity` в `src/lib/cart/actions.ts:205-213` не округляет,
  схема `cart_items.quantity = numeric(12,3)`. Покупатель может заказать 1.5 кг.
- Админ при редактировании заказа: `getQuantity` в `src/lib/admin/order-actions.ts:49-52`
  требует `Number.isInteger`. → админ не сможет отредактировать позицию с дробным количеством.
- **Действие:** определить, нужны ли дробные единицы (кг/м/т для B2B — обычно да). Если да —
  разрешить дробное `getQuantity` в админке (с округлением до 3 знаков). Если нет — ограничить
  корзину целыми и мигрировать. Рекомендация: разрешить дробное везде.

**2. Audit при удалении/скрытии документа — неполные метаданные (ТЗ 15.7 п.8)**
- ТЗ требует логировать: кто, когда, **тип документа, связанная сущность, имя файла**.
- `hideDocumentAction` в `src/lib/documents/actions.ts` (~строки 1024-1055) пишет audit с пустым
  `metadata`.
- **Действие:** перед скрытием прочитать документ (type, target, buyerCompanyId/orderId/sellerId,
  title и имя текущего файла из `document_versions`/`files`) и положить в `metadata` audit-события.

**3. Нет error/not-found/loading границ (ТЗ раздел 28 — «Ошибка загрузки» на всех экранах)**
- В `src/app` отсутствуют `error.tsx`, `not-found.tsx`, `loading.tsx`. При сбое запроса в
  server-компоненте показывается дефолтный экран Next, кастомного 404 нет.
- **Действие:** добавить:
  - `src/app/error.tsx` (global error boundary, клиентский, кнопка «Повторить» → `reset()`).
  - `src/app/not-found.tsx` (кастомная 404 со ссылкой в каталог).
  - по желанию — `loading.tsx` для тяжёлых разделов (`catalog`, `account/orders`, `admin/orders`).
  - Стиль — как на остальных страницах (см. `src/app/(public)/catalog/page.tsx`).

### P2 — консистентность

**4. Отчёт по комиссиям хардкодит 5 %**
- `src/app/(admin)/admin/commissions/page.tsx:149` считает `lineTotal * 0.05`, тогда как
  `order_items.commissionAmount` уже рассчитан по `sellers.commission_rate` на момент заказа,
  а экспорт (`src/app/(admin)/admin/orders/export/route.ts`) берёт сохранённое значение.
- При продавце со ставкой ≠5 % отчёт и экспорт разойдутся.
- **Действие:** в отчёте использовать `order_items.commissionAmount` (как экспорт), либо явно
  зафиксировать 5 % и убрать `commission_rate` из расчётов. Привести к единому источнику истины.

**5. Tie-break цены в каталоге не по дате публикации (ТЗ 8.5 п.3)**
- В модерации tie-break по `publishedAt` сделан верно, а в выдаче каталога
  `toProductListItems` в `src/lib/catalog/queries.ts:149-173` при равной минимальной цене
  `reduce` берёт первое попавшееся предложение.
- **Действие:** при равной цене выбирать предложение с более ранней датой публикации
  (`sellerOffers.moderatedAt`, fallback `createdAt`). Добавить поле в выборку и в reduce.

**6. Сбой Telegram не показывается покупателю (ТЗ 20.4 п.2)**
- `sendBuyerChatMessageAction` (`src/lib/chat/actions.ts:127-193`) всегда редиректит на
  `?sent=1`, даже если `deliverBuyerMessageToTelegram` упал (сообщение не теряется, админ видит
  ошибку, но покупателю «понятное сообщение об ошибке» не выводится).
- **Действие:** после `deliverBuyerMessageToTelegram` проверить `messages.deliveryStatus`; если
  `failed` — редирект на `?sent=1&deliveryWarning=1` и показать в чате мягкое предупреждение
  («Сообщение сохранено, оператор получит его при восстановлении связи»).

### P3 — защита от edge-кейсов

**7. Устаревание предпросмотра импорта**
- Между «валидацией» и «подтверждением» сохранённые в payload `categoryId/sellerId/
  existingProductId` могут устареть (категорию/продавца удалили) → возможна ошибка FK при
  создании нового товара. `confirmProductImportAction` в
  `src/lib/admin/product-import-actions.ts` берёт IDs из payload без перепроверки.
- **Действие:** в `applyResolvedRow` перед созданием нового товара перепроверить существование
  `categoryId` и `sellerId`; при отсутствии — пометить строку ошибкой, не падать транзакцией.

**8. Перезапись общей карточки товара при `update` от одного из нескольких продавцов**
- `approveProductModerationRequestAction` при `type !== 'offer_create'` перезаписывает поля
  master-товара (name/category/image) из формы продавца
  (`src/lib/admin/product-moderation-actions.ts:164-181`). Если к товару привязаны предложения
  нескольких продавцов, правка одного перепишет общую витринную карточку.
- **Действие:** запрещать `update`-заявку (или ограничивать набор изменяемых полей только ценой),
  если у товара есть опубликованные предложения более чем одного продавца. Низкий риск, но
  заложить защиту.

### Заблокировано материалами заказчика (раздел 38) — заложить «трубу»

**9. PDF счёта/договора: нет печати/подписи/логотипа, реквизиты поставщика захардкожены**
- `src/lib/invoices/pdf.ts` рисует только текст и линии под подпись; `src/lib/invoices/supplier.ts`
  содержит placeholder-реквизиты `ООО "ЖИЛАЛЬЯНС"` с пустым ОГРН; `src/lib/contracts/pdf.ts`
  аналогично.
- **Действие:** вынести реквизиты поставщика в ENV/настройки (не хардкод); добавить опциональную
  вставку изображений логотипа/подписи/печати из путей в ENV (если файл задан — `embedPng`,
  иначе текущий текстовый вид). НЕ выдумывать реквизиты — оставить заглушки и задокументировать,
  какие материалы нужны от заказчика.

### Опционально (матрица прав: «при разрешении интерфейсом»)

**10. Удаление документов покупателем/продавцом**
- Сейчас доступна только замена; удаляет/скрывает лишь админ. ТЗ формулирует это как
  опциональное. Реализовывать только если заказчик подтвердит необходимость.

## Приёмка

- [ ] Админ может отредактировать заказ с дробным количеством (или дробное запрещено везде).
- [ ] Audit при скрытии документа содержит тип, связанную сущность и имя файла.
- [ ] При ошибке загрузки любого экрана показывается аккуратный экран ошибки с «Повторить»; 404 кастомный.
- [ ] Отчёт по комиссиям и экспорт заказов дают одинаковые суммы комиссии.
- [ ] При равной минимальной цене на витрине выбирается предложение с более ранней публикацией.
- [ ] При сбое Telegram покупатель видит предупреждение, сообщение сохранено.
- [ ] Подтверждение импорта не падает, если категория/продавец удалены между фазами.
- [ ] `update`-заявка не перезаписывает карточку товара с предложениями нескольких продавцов.
- [ ] Реквизиты поставщика и изображения для PDF берутся из настроек/ENV, не из хардкода.
