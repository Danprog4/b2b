## Как заполнять

Этот файл — рабочий источник правды для ручной приёмки v1.1 и последующих фиксов. Один пункт = один проверяемый сценарий. Идите сверху вниз по разделам 1–13, затем закрывайте сводку из 55 критериев в разделе 14.

Для каждого пункта:

- `QA_STATUS` — результат проверки (значения ниже).
- `FIXES` — что нужно поправить, обычным текстом; для найденного дефекта начните строку с метки серьёзности: `[BLOCKER]` (нельзя запускать), `[MAJOR]` (ломает сценарий, обход есть), `[MINOR]` (косметика/мелочь).
- `EVIDENCE` — ссылка на скриншот, номер заказа/счёта, email, файл или короткий комментарий.

Допустимые значения `QA_STATUS`:

- `UNDONE` — не проверен или не принят (значение по умолчанию).
- `DONE` — сценарий вручную проверен и принят.
- `BLOCKED` — проверить нельзя без внешнего блокера; в `FIXES` укажите код блокера (`C-01…C-11`, см. карту ниже).
- `N/A` — сценарий неприменим в текущей сборке (обоснуйте в `FIXES`).

Условные обозначения в шагах:

- `§NN` — пункт первоисточника `Финал ТЗ`.
- `[AC-NN]` — связанный критерий финальной приёмки из раздела 14.
- Группы маршрутов Next.js в скобках (`(public)`, `(account)`, `(seller)`, `(admin)`) в URL **не входят**: файл лежит в `src/app/(public)/documents/...`, а открывается по адресу `/documents/...`.

## Внешние и окружение-зависимые проверки

Эти сценарии не закрываются на «голом» localhost. Часть **уже доступна на тестовом стенде** (тестовый бот, домен и т.п. настроены в тестовом режиме) — их можно и нужно проверять там. Часть ждёт материалов заказчика — её держите в `BLOCKED` с кодом `C-xx`.

**Доступно на тестовом стенде — проверяемо (ведите как обычные сценарии):**

- **Telegram-контур целиком**: уведомление оператору и ответ из Telegram в ЛК — работает на тестовом боте + webhook тестового стенда (CHAT-02, CHAT-03, CHAT-04).
- Реальная доставка email (счёт/договор/документы/статусы/восстановление пароля) — проверяема, если на стенде подключён email-провайдер и отправитель (`C-06`); иначе проверяйте создание записи в `email_outbox` и статусы очереди.
- Подгрузка по ИНН — проверяема, если на стенде стоит рабочий ключ DaData (`C-08`); иначе проверяйте корректную обработку ошибки.

**Ждёт материалов заказчика — держать `BLOCKED`:**

- PDF-счёт «в финале»: реквизиты юрлица, подпись, печать, логотип (`C-01/C-02/C-03/C-05`).
- Финальный шаблон и реквизиты договора (`C-04`).
- Тексты 4 инфостраниц и финальные баннеры (`C-09`).
- Нагрузка 300+ товаров, бэкап, боевой домен/SSL (`C-10/C-11`).

## Карта ролей и доступов

| Роль | Основная зона | Тестовые аккаунты/данные | Комментарий |
|---|---|---|---|
| Гость | публичная часть, корзина до оформления | заполнить перед QA | не должен видеть ЛК, документы, продавцов, админку |

| Продавец B | проверка конкурентов и offer-flow | заполнить перед QA | нужен для нескольких предложений |
| Администратор | админ-панель | заполнить перед QA | desktop-only |
